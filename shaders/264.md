## Overview

### Why

The Composable card on the homepage, tracked in SHA-217, stacks a Source, FlutedGlass, and Grain in one live scene. Shaders had no glass Effect to put in the middle. This pull request adds the FlutedGlass core that the card needs.

### Behavior change

`<FlutedGlass />` is a new Effect. Mount it after a Source inside a `<ShaderScene>`, and you see that Source through vertical strips of glass, 40 CSS pixels wide. Each flute shows a squeezed copy of the image beneath it. A highlight runs down the wall that faces the light, which comes from the upper left, and a soft shadow sits in each groove. Eight props set the glass and the light, and every prop except `highlightColor` takes a static value or an animation signal.

The engine exports `fluteSurface`, so a Mode 2 shader can bend and light its own texture with the same math. The docs site has a FlutedGlass page, in a new Warp group under Effects.

### Checks

These are the checks that the pull request and its CI report:

- Every CI job passed on the head commit, including unit tests and visual regression.
- The component's unit tests check that FlutedGlass registers one UV warp and one color transform, survives Strict Mode, and takes new prop values without registering either pass again.
- The `fluteSurface` unit tests check only that it builds its nodes from numbers, from nodes, and from values out of range. The pixel checks test its output.
- The visual-regression spec compares the docs page's canvas with the `fluted-glass-default` baselines. Five pixel checks on a stripe probe test the bend, the highlight, the shadow, inert glass, and a transparent scene.
- ShaderMonitor on `/dev/fluted-glass-benchmark` timed the GPU at 485×308 CSS pixels and 2x, on an M1 Max in headless Chromium on WebGPU. MeshGradient alone took 0.24 ms, and MeshGradient under the glass took 0.28 ms. The glass adds 0.04 ms against a 0.2 ms budget. Each figure is the median of three loads.

### Not covered

- A UV warp mounted before FlutedGlass, such as Dither's, hands the glass a coordinate it already moved. The bend and the light then read the surface at slightly different points. SHA-267 changes how UV warps stack.
- FlutedGlass bends only what Sources drew, so glass mounted after Grain leaves the grain unbent. [ADR 0002](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/docs/adr/0002-cursor-effects-not-cursor-props.md#consequences) accepted that limit for every UV warp.
- FlutedGlass has no color split or blur yet. [ADR 0004](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/docs/adr/0004-effects-resample-by-wrapping-the-sampler.md) decides how they will sample the scene.
- FlutedGlass works only in Mode 1. Mode 2 gets the `fluteSurface` primitive and no component.

## Mount FlutedGlass after a Source

`FlutedGlass` is an [Effect](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/GLOSSARY.md#scene-model), a component that acts on the image beneath it instead of drawing its own. [Mount it after the Sources it should bend](packages/shaders/src/components/fluted-glass/fluted-glass.tsx#L82-L90), inside a `<ShaderScene>`. It bends only what Sources drew, so an Effect such as Grain goes after the glass, where the order you write matches what you see.

FlutedGlass works only in Mode 1, where `<ShaderScene>` owns the canvas. The scene draws its Sources into a texture, an image held on the GPU. The scene's output stage then draws that texture to the canvas, and it runs each Effect's code as part of that draw. In [Mode 2](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/apps/docs/content/docs/react/guides/three-r3f.mdx), you bring your own r3f `<Canvas>` and get the flute math as the `fluteSurface` primitive instead.

`FlutedGlass` sets [the props and their defaults](packages/shaders/src/components/fluted-glass/fluted-glass.tsx#L91-L100), then hands them to `FlutedGlassShader`. `fluteWidth` is in CSS pixels, so a [flute](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/GLOSSARY.md#fluted-glass) keeps its size on a 1x and a 2x display. `angle` uses [the degrees that LinearGradient uses](packages/shaders/src/components/fluted-glass/fluted-glass.tsx#L29-L36), so the default of 90 runs the flutes bottom to top. `refraction` sets how far each flute bends the image, and 0 leaves the image unchanged.

`crossSection` sets the [cross-section](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/GLOSSARY.md#fluted-glass), the shape of a flute seen from its end. It takes a number from 0 to 1 or [one of three names](packages/shaders/src/components/fluted-glass/fluted-glass.tsx#L12-L21). Each name is a point on that 0-to-1 dial, and [the component turns a name into its number](packages/shaders/src/components/fluted-glass/fluted-glass.tsx#L109-L111). The shader sees only numbers, so an animation signal can sweep the dial and morph a prism into a flat top.

`lightAngle` runs [counterclockwise, like `angle`](packages/shaders/src/components/fluted-glass/fluted-glass.tsx#L52-L61), so turning both by the same amount keeps the light on the same wall. The spec gave the light a clockwise compass, and the author approved the change on SHA-266.

Still glass draws nothing that changes over time, so the glass [votes idle](packages/shaders/src/components/fluted-glass/fluted-glass.tsx#L101-L104). When every component in a scene votes idle, the scene stops drawing frames until something changes. Moving a prop asks for a new frame.

The package index [exports the component and its prop types](packages/shaders/src/components/index.ts#L37-L38).

## Repeat space into flutes

From here on, the code is TSL, the three.js shading language that you write in JavaScript. A TSL function such as `fract()` or `dot()` returns a node, not a number. The nodes form a graph that three compiles into a fragment shader, a GPU program that runs once for every pixel. So `fluteSurface` itself runs once, when the shader is built, and the expressions it returns run on the GPU for each pixel.

[`fluteSurface`](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L108-L111) takes a position and works out the glass at that point. The position is a 2D vector in any units with y up, and `fluteWidth` shares its units. It [returns four nodes](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L56-L82): the bend, the slope, `fromCenter`, and `steepness`.

Each option [takes a number or a node](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L112-L115). `float()` turns a number into a node, so the same code accepts a fixed width or a uniform. A uniform is a value that the CPU writes and the GPU reads at each draw, so a slider can move it without a new shader. The `max()` keeps the width above 0, and `clamp()` holds the cross-section between 0 and 1.

The flutes run along the angle's direction, (cos, sin). [The direction across the flutes is that direction turned a quarter turn clockwise](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L120-L124), so at the default of 90 degrees it points left to right, over vertical flutes.

[`dot()` projects the position onto the across direction](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L141). The result is the position's signed distance across the flutes, and dividing by the width counts that distance in flutes. `fract()` keeps the part after the decimal point, and that is how a shader repeats space. [Every flute gets the same 0-to-1 ramp](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L142), whatever its number. The +0.5 shifts the ramp so that its middle, a flute's center, lands on each whole number. At each [groove](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/GLOSSARY.md#fluted-glass), the ramp jumps from 1 back to 0, and that jump breaks the image into strips.

[`fromCenter`](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L144-L148) folds the ramp into a distance from the flute's center, 0 at the center and 1 at either groove. Both sides of a groove read 1, so `fromCenter` has no jump. The shadow in step 8 depends on that.

The engine [exports `fluteSurface` and its types](packages/shaders/src/engine.ts#L70-L74), so a Mode 2 shader can call it on its own coordinates.

## Smooth each groove over one pixel

MSAA, or multisample antialiasing, is the GPU's own edge smoothing, and it works on the edges of triangles. A Shaders scene draws each component as one quad, a rectangle of two triangles that covers the canvas, and it [turns MSAA off](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/docs/agents/tsl.md#the-no-depth-gotcha-a-webgpu-scene-has-no-depth-buffer-and-no-msaa). Every edge you see comes from shader math, so the shader has to smooth it. Left alone, the ramp's jump lands on whole pixels, and [a slanted groove draws a staircase](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L153-L156). The fix replaces the jump with a slope one pixel wide.

To learn how many flutes one pixel spans, [the shader asks the GPU](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L158-L165). The GPU shades pixels in 2×2 blocks, so each pixel can read how much a value changes to its neighbor. `fwidth()` adds that change across and down. `fwidth(flutePhase)` is how many flutes one pixel spans, 0.025 for a 40-pixel flute. It measures the phase before `fract()`, because the ramp's jump would read as a huge change. Only a fragment shader shades in those blocks, so `fluteSurface` works only in a fragment shader.

Then [`smoothstep()` and `mix()` ease the ramp toward its mirror image](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L167-L177), 1 minus the ramp, over the last pixel before each groove. `smoothstep(a, b, x)` returns 0 below `a`, 1 above `b`, and a smooth curve between. `mix(a, b, t)` blends `a` into `b` by `t`. Both sides of a groove now arrive at 0.5, the flute's center, where the glass is flat. The groove pixel then shows the image right at the groove instead of either flute's bent copy. Away from the grooves the blend is 0, and the ramp is unchanged. [Paper's fluted-glass shader](https://github.com/paper-design/shaders/blob/1923e9f536ea079e2a95d23291cbfacfd69d37f6/packages/shaders/src/shaders/fluted-glass.ts#L160-L168) has the same function, `smoothFract`.

[`GROOVE_SMOOTHING`](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L93-L96) sets the band's width, one pixel. At 0 the staircase comes back, and above about 2 the grooves blur. Last, [`fluteOffset` stretches the smoothed ramp](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L179-L181) to run from -1 at one groove, through 0 at the center, to 1 at the other.

## Shape the cross-section with an exponent

The [cross-section](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/GLOSSARY.md#fluted-glass) is one number, an exponent that shapes the slope.

[The dial picks the exponent](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L194-L200) on a doubling scale. `dialFromRound` runs from -1 at a prism, through 0 at round, to 1 at flat. `select()` is the TSL version of the `? :` operator. It picks the prism end below 0 and the flat end above, and `pow()` raises that end to the dial's distance from round. Anything to the power 0 is 1, so 0.5 is exactly round, whatever the ends are. With [ends of 1/16 and 16](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L87-L92), the exponent doubles every eighth of the dial, so a sweep morphs the shape evenly.

[The slope's size is the distance from the center, raised to the exponent](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L205-L221). That distance runs from 0 to 1, so a power bends the curve between without moving its ends. The center stays flat, and the groove stays steepest. An exponent of 1 gives a round lens. Below 1, the slope jumps to nearly full just off the center, and the flute becomes a prism, two flat faces that meet at a ridge. Above 1, the glass stays flat across the top and turns steep right at each groove.

`pow()` needs a base of 0 or more, so [the code raises `fromCenter` and lets the offset carry the sign](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L235). Raising the smoothed offset itself looks simpler, but [it would undo the groove smoothing on a prism](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L228-L231). x^(1/16) is still 0.82 at x = 0.045, so the slope would stay near full until a sliver from the groove, and the grooves would staircase again. The `max()` keeps the base off 0 at the center, where a prism's negative power, the exponent minus 1, would divide by zero.

A prism's ridge jumps too, in the middle of the flute. [A second `smoothstep()` fades the slope in over the first pixel either side of the center](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L237-L246). Then [the slope points along the across direction](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L247), toward the nearer groove.

[`steepness`](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L249-L254) takes the same power of `fromCenter`, without the groove smoothing. Away from the grooves it equals the slope's length. On a groove's own pixel, where the smoothing pulls the slope through 0, the steepness keeps climbing to 1. Step 8 shades with it for that reason.

## Measure the glass in device pixels

[`FlutedGlassShader`](packages/shaders/src/components/fluted-glass/shader.tsx#L125-L134) is the GPU half of the component. It calls `fluteSurface` twice, once to bend the image and once to light it. This step covers what the two calls share.

Each prop lives in [a uniform](packages/shaders/src/components/fluted-glass/shader.tsx#L137-L145), through `useAnimatableUniform`. Writing a new value into a uniform never rebuilds the shader, so a slider drag stays smooth. An animation signal writes into the same uniform on each frame. The [uniform-stability gotcha](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/docs/agents/tsl.md#the-uniform-stability-gotcha-push-prop-changes-through-uniforms) in the agent docs explains why.

`fluteWidth` is in CSS pixels, but the shader counts device pixels, so [a pixel-ratio uniform converts between them](packages/shaders/src/components/fluted-glass/shader.tsx#L164-L195). It reads the renderer's pixel ratio, which respects the scene's `maxDPR` limit. `useResize` fires again when the window moves to another monitor or the browser zooms, and the effect writes the new ratio. Each write [asks the scheduler for a frame](packages/shaders/src/components/fluted-glass/shader.tsx#L187-L189), because a write into a uniform repaints nothing on a scene that has stopped drawing. That trap is the [bare-uniform-write gotcha](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/docs/agents/tsl.md#the-bare-uniform-write-gotcha-a-bare-uniform-write-repaints-nothing) in the agent docs.

[`surfaceAt`](packages/shaders/src/components/fluted-glass/shader.tsx#L197-L214) turns a pass coordinate into the primitive's frame. A pass coordinate is a point on the canvas, from 0 to 1 from the top-left corner, with y down. Subtracting 0.5 measures from the canvas center, so the middle flute sits in the middle of the canvas and the flutes turn around it as `angle` changes. `screenSize` is the size of the drawing buffer, the grid of device pixels that the GPU draws into. Multiplying by it turns 0-to-1 into pixels, so a flute is as wide on a wide canvas as on a tall one. [`flipY`](packages/shaders/src/components/fluted-glass/shader.tsx#L101-L105) points y up, the frame the primitive measures `angle` in.

Both passes call `surfaceAt`, so the light lands where the image bends.

## Bend the image by sampling it somewhere else

Glass doesn't move pixels. It changes which point of the scene behind it reaches your eye, and a shader bends an image the same way, by reading it at another point. [`fluteSurface` returns that offset as the bend](packages/shaders/src/primitives/flute-surface/flute-surface.ts#L259-L269), the slope times `refraction`, in half flute widths. On a round flute at a `refraction` of 1, a point at offset x from the center reads the image at 2x. The flute then shows twice its own width of image, squeezed. The bend points away from the center on both sides, so it squeezes the copy instead of stretching it.

The output stage reads the scene's texture to draw the canvas. A [UV warp](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/GLOSSARY.md#scene-model) changes where it reads. [`useBasePassUv`](packages/shaders/src/components/fluted-glass/shader.tsx#L219-L233) registers one. Its callback receives the 0-to-1 coordinate that the texture is about to be read at, and returns a new one. FlutedGlass [turns the bend back into the pass's frame](packages/shaders/src/components/fluted-glass/shader.tsx#L225-L228) and adds it.

Near the canvas edge, the bend can point off the canvas, where the texture has nothing. The sampler, the GPU unit that reads a texture, would repeat the edge pixel there and draw a smeared strip. [`mirrorOntoCanvas`](packages/shaders/src/components/fluted-glass/shader.tsx#L107-L123) folds the coordinate back instead, as if the image were mirrored past each edge. `fract(x / 2) * 2 - 1` runs from -1 to 1 over every 2 units, and 1 minus its absolute value is a triangle wave. On 0 to 1 the wave returns x unchanged. Past either edge it walks back, so 1.1 reads 0.9.

The glass reads the scene once per pixel, so a UV warp is enough for now. The glossary calls an Effect's rule for building a pixel from samples a [resample](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/GLOSSARY.md#scene-model), and a UV warp is a resample that takes one sample. The planned color split takes 3 samples, and the planned blur takes 12. [ADR 0004](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/docs/adr/0004-effects-resample-by-wrapping-the-sampler.md), added in this pull request, decides how they get them. Each Effect will get a function that samples everything beneath it, and return a new function in its place. The ADR [rejects having FlutedGlass read the scene texture itself](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/docs/adr/0004-effects-resample-by-wrapping-the-sampler.md#considered-options), because that read would skip every UV warp beneath the glass. A CursorRipple under the glass would vanish.

## Shade the grooves in a color transform

FlutedGlass lights the glass in a color transform, which [`usePostProcessPass`](packages/shaders/src/components/fluted-glass/shader.tsx#L238-L248) registers. Its callback receives each pixel that the scene drew, already bent by the warp, as `input`, and returns a new color. The warp and the color transform draw in the same output quad. `uv()` is the pixel's own pass coordinate, so `surfaceAt(uv())` is the glass at this pixel.

[The shadow](packages/shaders/src/components/fluted-glass/shader.tsx#L250-L264) multiplies three values. `smoothstep()` climbs from 0 to 1 over the outer half of the way from the center to the groove, a share that [`SHADOW_WIDTH`](packages/shaders/src/components/fluted-glass/shader.tsx#L96-L99) sets. `steepness` keeps the shade where the glass is steep. A flat top darkens only on its walls, and a prism, steep from ridge to groove, keeps the whole band. The third value is the `shadow` prop.

Both `fromCenter` and `steepness` skip the groove smoothing, and the shadow needs them to. The smoothing pulls the slope to 0 on the groove's own pixel, so a shadow built from the slope would leave a bright line down the middle of each dark groove. That bright line is why `fluteSurface` returns two more values next to the slope. Multiplying the color darkens it without changing alpha, the pixel's opacity, so a transparent pixel stays transparent.

[The warp starts from `uv()` too](packages/shaders/src/components/fluted-glass/shader.tsx#L242-L245), as long as it is the first warp in the scene. A UV warp mounted before FlutedGlass, such as Dither's, hands the glass a moved coordinate. The bend and the light then read the surface at slightly different points, until SHA-267 changes how warps stack.

## Light the walls with a Blinn-Phong highlight

The highlight is specular light, the bright reflection on a shiny surface. Three directions decide it, each a vector one unit long.

[The surface normal](packages/shaders/src/components/fluted-glass/shader.tsx#L270-L275) is the direction the glass faces. Flat glass faces straight out of the screen, (0, 0, 1). Using the slope as the normal's x and y tilts it, so a wall's normal leans the way the wall faces. At a groove the slope is 1, and the normal leans 45 degrees. `normalize()` scales the vector back to one unit long.

[The direction toward the light](packages/shaders/src/components/fluted-glass/shader.tsx#L277-L288) turns around the screen with `lightAngle`. [`LIGHT_HEIGHT`](packages/shaders/src/components/fluted-glass/shader.tsx#L88-L92) lifts it 30 degrees off the glass. The height never changes, so its cosine and sine come from JavaScript's `Math.cos` and `Math.sin`, which run once, when the shader is built. TSL's `cos()` and `sin()` run on the GPU for every pixel, and the code uses them only for the angle, which a uniform can change.

The third direction is toward the eye, which looks straight at the screen from (0, 0, 1). A mirror reflects light into the eye where its normal points halfway between the light and the eye. Blinn-Phong measures how close the normal comes to [that halfway vector](packages/shaders/src/components/fluted-glass/shader.tsx#L290-L302). `dot()` of two unit vectors is the cosine of the angle between them, so it is 1 where the normal points exactly halfway. Raising it to the power of [`HIGHLIGHT_SHARPNESS`](packages/shaders/src/components/fluted-glass/shader.tsx#L93-L95), 32, keeps values near 1 and crushes the rest. The highlight narrows to a band on the part of each wall that leans toward the light. The `max()` keeps the base of `pow()` at 0 or more.

[The light scales with the `highlight` prop and with the pixel's alpha](packages/shaders/src/components/fluted-glass/shader.tsx#L304-L310), so a transparent pixel gets no light. The highlight color multiplies last, as an argument, because a method chained off a vec uniform compiles and then gives wrong values on the GPU. That trap is the [vec-uniform gotcha](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/docs/agents/tsl.md#the-vec-uniform-gotcha-pass-vec-uniforms-as-arguments-never-as-chained-receivers) in the agent docs.

[The color uniform](packages/shaders/src/components/fluted-glass/shader.tsx#L147-L162) holds `highlightColor` as linear RGB, in a `Vector3` made once. A new color writes into the same vector, so a color change never rebuilds the color transform.

## Test the look with a baseline and pixel checks

[The default story](apps/docs-tests/visual/fluted-glass.spec.ts#L6-L10) loads the FlutedGlass docs page and compares its canvas with a stored screenshot. The `?visualTest=1` query makes the capture repeatable. Each baseline has [two platform copies](https://github.com/campdotdev/shaders/blob/84cc41703117a566f6e181dd8aec5ec7ce889521/docs/development/visual-regression.md#two-platform-baselines), and both appear with this step's code. CI runs on Linux and compares against the `-linux.png`. A local run on a Mac compares against the `-darwin.png`, because Chromium draws fonts and edges differently on each OS.

A baseline proves only that the look didn't change. It can't prove the glass works, because a baseline regenerated from broken glass passes its own screenshot. So [five pixel checks](apps/docs-tests/visual/fluted-glass.spec.ts#L193-L200) load the dev route `/dev/fluted-glass-probe`, which draws hard diagonal stripes under the glass. Each check compares the brightness of two loads with different props:

- [The stripes break at the grooves](apps/docs-tests/visual/fluted-glass.spec.ts#L201-L206) far more often than through glass with a `refraction` of 0.
- [The highlight lands on the walls that face the light](apps/docs-tests/visual/fluted-glass.spec.ts#L212-L220), and the walls that face away gain less than a quarter as much.
- [A flat top's shadow stays on its walls](apps/docs-tests/visual/fluted-glass.spec.ts#L227-L236) and takes less than 2% off the flat middle.
- [Inert glass leaves the Source unchanged](apps/docs-tests/visual/fluted-glass.spec.ts#L240-L245), within one brightness level.
- [A transparent pixel gets no highlight](apps/docs-tests/visual/fluted-glass.spec.ts#L249-L254), even at full highlight and full shadow.
